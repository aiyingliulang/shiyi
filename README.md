# 食忆 v1.2.0（Android）

个人美食消费记录 App：记录外卖、团购到店和线下堂食的**本人实付金额**、时间、平台和整体评分，帮你查历史价格、找值得回购的、避开踩过的雷。识别全部在本机完成；联网只用于查条码和你自己的坚果云备份，都可关闭。

## 更新记录

### v1.2.0
- **定期自动备份**（设置 → 定期自动备份）：选每天 / 每 3 天 / 每周，备份到手机上的文件夹、坚果云，或两处都备份。
  - 后台备份时没法问你密码，所以开启时设一次备份密码，用手机安全芯片里的密钥加密保存在本机（和坚果云应用密码的保存方式一样）。恢复时仍要输入这个密码。关闭自动备份会删除保存的密码。
  - 数据自上次自动备份以来没有变化时跳过，不会产生一堆一样的文件。手机文件夹里保留最近 10 份自动备份（文件名 `shiyi-auto-日期-时间.shiyibak`，不会删你手动备份的文件）；坚果云和手动云备份一起保留最近 10 份。
  - 备份到手机文件夹的文件在卸载 App 后仍然保留（建议在“下载”里建一个“食忆备份”文件夹）。
  - 保存设置后会立即备份一次，确认密码和位置都可用。之后每 12 小时检查一次是否到期；电量低或存储空间不足时等一等再备份。没网时上传失败，会在 30 分钟后自动重试，最多 3 次。
  - 真我等手机会限制后台任务，如果到期了还没备份，打开 App 时会自动补上。想更准时，可以在系统设置里把食忆的“耗电管理”设为“允许后台运行”。
  - 失败时，设置页会显示原因，点一下即可重试。
- **首页备份提醒**：有数据但 14 天没有备份过（任何一种方式都算），或自动备份失败时，首页顶部会提醒；点“稍后”7 天内不再提醒。
- **首页“本月实付”下面显示上个月的总额**，方便对比。
- 修复：手动备份 / 恢复和后台自动备份同时进行时可能互相覆盖临时文件，现在会排队依次执行。
- 新增依赖 WorkManager（Android 官方后台任务库），因此 App 多了“开机启动”“防止休眠”“前台服务”几项普通权限（不需要你授权），用于开机后恢复定时任务、保证备份不被中途打断。仍然不读取网络状态，没有广告和统计 SDK。

### v1.1.0
- **按评分自动归类，不用再确认**：8～10 分自动算“值得回购”，1～4 分自动算“不再推荐”，5～7 分算“一般”（外卖和零食统一这三档）。例外：低分但差评原因全是配送问题（送慢、洒漏等），归为“一般”，避免冤枉菜品。想改的话在详情页或录入页选“值得回购 / 一般 / 不再推荐”，手动选择优先。
- **去掉“美食档案”，合并“清单”**：底部导航改为 首页 / 记录 / 零食 / 设置。原来的清单变成“记录”页顶部的筛选：全部 / 值得回购 / 不再推荐 / 一般 / 未评分。同一家店、同样标题的消费会自动归在一起，详情页直接显示历史次数、最低/最高价，以及和上一次比贵了还是便宜了。录入时填好店名和标题，会提示“你吃过 N 次，上次几分”；这家店有不再推荐的，也会直接列出来。
- **平台新增“抖省省”**，截图识别也认得。
- **补录旧订单不用强制选时间**：日期一栏改为“今天 / 昨天 / 前天”一键选，或点日期直接改；时间是可选的。截图里没有时间时，会提示“先按今天记录，点一下日期改掉即可”。
- **评价原因分组**：分成“好的方面 / 不足之处 / 配送问题”三组。评分高时好评组排在前面，评分低时差评组排在前面。零食也一样。
- **联网（都可在设置关闭）**：
  - 扫条码后联网查商品名称、品牌、规格并自动填好（数据源 Open Food Facts，只发送条码数字）。国内零食覆盖率一般，查不到时手动填一次，下次扫码就能从本地认出。
  - 拍零食包装照片后，会离线识别包装上的文字，点一下就能填入名称；“净含量 70g”会自动填进规格。
  - **坚果云 / WebDAV 云备份**：先用你的备份密码加密再上传，云端只看得到密文；自动保留最近 10 份；可以从云端选一份恢复（先校验再确认覆盖）。坚果云应用密码用手机安全芯片里的密钥加密保存。
- **图片压缩**：保留的订单截图改为压缩保存（宽度不超过 1280 像素，长截图保留完整高度，文字仍然清晰）；零食照片保存时压缩到长边 1600 像素。云备份**默认带零食照片、不带订单截图**（设置里可开关），放进云备份的图片会再压缩到约 1080 像素，每张大约 100KB。恢复时，备份里没有的那类图片保留手机上已有的。
- App 现在申请了网络权限，但仍然不读取网络状态。识别库自带的使用统计已被关闭（移除了它的上报通道），没有广告和统计 SDK。

### v1.0.2
- **修复闪退的真正原因**（根据诊断日志定位）：录入页的“历史店铺建议”和零食页的“品牌建议”两个查询，SQL 里的 `ESCAPE '\'` 写在了 Kotlin 普通字符串里，`\'` 被当成转义的单引号，生成了非法的 `ESCAPE ''`。所以截图识别出店名、或在零食里输入品牌时就会崩溃。v1.0.0 里截图识别的闪退也是同一个原因。
- 新增测试：所有带模糊搜索的查询都在真实 SQLite 上执行一遍（包括 `%`、`_`、`\` 等特殊字符）。建议类查询即使失败，也不会再影响录入。
- **识别规则按真实美团截图修正**：“合计 共减¥17.63(…) ¥12.37”现在取 ¥12.37；“共减”“已减”“省”后面的金额、运费、打包费、优惠券、“13 元餐补券”都不再进入候选；“商品总价”不再被当作合计；店名去掉“外卖”前缀；“数量 ×1”单独成行时，能从上一行取到商品名。

### v1.0.1
- **修复：截图识别闪退。** OCR 改在独立进程（`:ocr`）中运行，识别库即使崩溃或内存不足，也只会结束识别进程，主界面不再闪退，会提示“识别异常，请手动填写”。长截图改为分块解码，不再把整张长图读进内存；缩略图和大图预览也限制了解码尺寸。
- **修复：在“清单”页点“首页”有时没反应。** 原因是底部导航“保存/恢复页面状态”的机制把刚离开的页面恢复了出来，现在回首页时会直接回到首页。
- **新增：诊断日志。** 本机记录闪退调用栈和系统给出的异常退出原因（包括原生库崩溃、被系统因内存不足结束），在“设置 → 诊断日志”里查看和复制。从 v1.0.0 覆盖安装后，第一次打开还能读到系统记下的旧版本闪退原因。日志只存在本机，不会上传。
- **新增：零食模块（底部“零食”页）。** 详见下方第三节。
- 数据库从 v1 升级到 v2（只新增零食表），已用迁移测试验证原有数据完整保留。备份格式升级到 2，**v1.0.0 的旧备份仍可恢复**。

## 一、直接安装

`食忆-v1.2.0-release.apk`：正式签名版，安装到真我 GT5 Pro 即可使用。

1. 把 APK 发到手机（数据线、微信文件传输助手、网盘均可），点开安装，按提示允许“安装未知应用”。
2. 如果真我系统提示“未经过安全检测”，选“继续安装”。App 只申请了网络权限（用于查条码和坚果云备份，可在设置关闭），没有相册、相机、存储权限。
3. 已安装旧版的话，直接安装新版覆盖即可，**数据保留**（签名相同、版本号更高）。保险起见，可以先在旧版里做一次加密备份。
4. `食忆-v1.2.0-debug.apk` 是调试版，包名是 `com.shiyi.app.debug`，可以和正式版同时安装，数据互不影响，适合测试。

> **签名密钥**：`keystore/shiyi-release.jks` 和 `keystore.properties` 是正式版的签名密钥和密码，请妥善保存，不要公开。以后升级 App 必须用同一把密钥签名；密钥丢了就只能卸载重装，卸载会清空数据，所以务必先做备份。

## 二、自己构建

环境要求：JDK 17 或更高版本、Android SDK（Platform 36、Build-Tools 36）。用 Android Studio 打开本目录即可，它会自动生成 `local.properties`。

```bash
# Windows 用 gradlew.bat
./gradlew assembleDebug        # 调试版 → app/build/outputs/apk/debug/
./gradlew assembleRelease      # 正式版（需要 keystore.properties）→ app/build/outputs/apk/release/
./gradlew testDebugUnitTest    # 单元测试 + 备份恢复端到端测试
```

技术栈：Kotlin 2.2 · Jetpack Compose（Material 3）· Room 2.8 · DataStore · ML Kit 中文文字识别（模型打包在 APK 内）· AGP 8.13 · compileSdk/targetSdk 36 · minSdk 26 · 只打包 arm64-v8a 架构。

## 三、功能对照

| 大纲要求 | 实现 |
|---|---|
| 三种场景 | 外卖、团购到店（购买时间和实际消费时间分开记录，实际消费时间可为空）、线下堂食（只要求填店铺和实付金额） |
| 三种录入入口 | 截图识别（系统照片选择器，最多 9 张）、从其他 App 系统分享（单图、多图、文字或链接）、手动录入 |
| OCR | ML Kit 打包式中文模型，离线运行，首次启动不需要下载；长截图会切片识别；同一行的“标签 + 金额”会合并后再解析 |
| 字段解析 | 本地规则识别平台、场景、店铺、商品、实付、下单时间、核销时间和订单号；**识别不确定的字段一律留空**，同时给出候选让你点选 |
| 一笔消费一个评分 | 1～10 分可跳过，按 1～3 / 4～6 / 7～8 / 9～10 分四档 |
| 归类 | 按评分自动：8～10 值得回购、5～7 一般、1～4 不再推荐（只因配送问题的低分除外）；可手动改。只针对这一笔消费，不会拉黑整家店 |
| 历史价格 | 同店同标题的消费自动归在一起（跨平台），显示次数、最低/最高价、和上一次的差价 |
| 列表筛选 | 关键词（店铺、标题、菜名、备注、档案名）、平台、场景、评分档、价格区间、5 种排序 |
| 备份 | AES-256-GCM 加密，PBKDF2-SHA256 迭代 60 万次；备份包含数据库和保留的图片；支持密码提示、先验证再恢复；可定期自动备份到手机文件夹和/或坚果云 |
| CSV | 带 UTF-8 BOM，Excel 直接打开中文不乱码；防公式注入 |
| 零食 | 一款零食一条记录：包装照片、名称、品牌、口味、条码、购买地点、价格、评分、结论（好吃会再买 / 一般 / 难吃别再买）、原因（太甜、香精味、包装好看但难吃……）。**在超市拍一下条码就能查到以前的评价**，吃过且难吃会醒目提示“别买”；也能手动输入条码，或按名称、品牌搜索；列表是照片墙，方便凭包装认出来 |
| 隐私 | 联网只用于查条码（只发条码数字）和坚果云加密备份，都可关闭；识别库统计已关闭；关闭系统自动备份；订单号只存 SHA-256 指纹；可选禁止截屏 |

### 零食模块的设计说明

- **拍条码不需要相机权限**：调用系统相机拍一张照片，App 在本机离线识别条码（ML Kit 打包模型，同样在独立进程中运行）。
- **零食默认保留包装照片**：和订单截图不同，包装照片本身就是用来“下次认出来”的。照片会压缩到长边 1600 像素左右，每张大约 200～400KB。
- **结论按评分自动建议**：1～4 分建议“别再买”，5～7 分建议“一般”，8～10 分建议“会再买”，可以手动改。
- **一款一条记录**：再次购买时直接修改评分和结论，不会重复建多条。同一条码不同口味可以另建一条，录入时会提示“这个条码已经记录过”。
- 首页搜索也会搜到零食；备份、恢复和 CSV（单独一份“零食 CSV”）都包含零食。

## 四、对大纲的调整和补充

大纲整体很合理，下面是我开发时自行做的调整，供你确认：

1. **去掉独立的“交易类型”字段**：它和“消费场景”重复，保留场景就够了。
2. **订单号只存指纹，不存明文**：大纲写的是订单号默认不长期保存，但不保存就做不了去重。所以改为只保存不可逆的 SHA-256 指纹，既能去重又不留明文，设置里可以关掉。去重另外还会检查“同店、同金额、10 分钟内”的记录，命中时提示你，由你决定是否仍然保存。
3. **“值得回购”合并为两个来源**：一是商品档案上标记的“值得回购”，二是消费记录上选了“愿意回购”的，不再额外设一个“标记记录”的开关，避免两套概念重复。
4. **（v1.1 起）“值得回购 / 一般 / 不再推荐”按评分自动归类**，不需要确认，也可以手动改。
5. **多张截图合并为一笔消费**：一张订单常常要截好几屏。如果要录多笔不同的消费，请分几次导入。
6. **金额不自动猜**：只有出现“实付、实付款、合计”这类明确标签时才自动填入；其他金额只作为候选让你点选，优惠、配送费、打包费、红包都会被排除。
7. **录入时提示店里的雷**：输入店名后，如果这家店有不再推荐的消费，会在页面里直接列出来，并显示上次的消费情况。不弹窗，也不会拉黑整家店。
8. **配送原因单独标记**：外卖的评价原因里，“配送慢、洒漏、送错、送到已凉”等标签带“配送”标识，便于和商品本身的问题区分。
9. **备份用分块加密格式**：每 1 MiB 一块，单独认证，能防篡改、防重排、防截断；图片多时也不会占满内存。恢复先解密到临时目录并做完整校验，校验通过后在一个事务里替换数据，任何一步失败都不会改动现有数据。
10. **只打包 arm64**：APK 约 21 MB（含中文 OCR 与条码模型）。如果要在 x86 模拟器上跑，在 `app/build.gradle.kts` 的 `abiFilters` 里加上 `"x86_64"`。
11. **为未来同步预留**：UUID 主键、创建和更新时间、Repository 抽象、Room schema 导出（`app/schemas/`），以及不允许破坏性迁移的约定。删除目前是直接删除，以后做同步时需要再加“墓碑”字段。
